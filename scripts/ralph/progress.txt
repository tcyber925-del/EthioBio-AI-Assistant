## Codebase Patterns
- Socratic mode is a boolean field on AgentState (`socratic_mode: bool`) passed through the LangGraph pipeline
- TutorNode and TutorAgent both accept a `socratic_mode` parameter to switch between standard and Socratic system prompts
- Telegram bot stores session-scoped toggles in `context.user_data`
- API request schemas always default new optional fields (`socratic_mode: bool = False`, `hint_level: int = 0`, `reveal_answer: bool = False`) to maintain backward compatibility
- Hint progression uses a `_build_system_prompt()`/`_build_node_prompt()` factory pattern that selects prompt based on `socratic_mode`, `hint_level`, and `reveal_answer` — reusable for other prompt variants
- Graph agent (`TutorAgent`) and graph node (`TutorNode`) have parallel prompt construction logic — both must be updated when prompt behavior changes
- Telegram hint flow: store `ask_question` + `hint_level` in `context.user_data`, upgrade hint level on each call, pass to agent
- SOCRATIC_SYSTEM_PROMPT uses STRUCTURED RESPONSE FORMAT (ACKNOWLEDGE → GUIDE → PROMPT) to enforce guiding question generation
- `guiding_question` field in AgentState/GraphOutput provides tracking for extracted guiding questions
- Always revert half-baked changes from other stories before committing (`git checkout HEAD -- <file>`)
