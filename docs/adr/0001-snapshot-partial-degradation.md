# ADR 0001: LearnerSnapshot uses partial degradation on source failure

The SnapshotBuilder assembles data from 7 independent sources (mastery, ability, misconceptions, recovery, SRS, memory, gamification) via parallel loaders. When one source fails (e.g., gamification DB is unreachable), the snapshot is returned with `degraded: bool = True` and `degraded_sources: list[str]` rather than failing the entire build with HTTP 500. Each source loader catches its own exceptions and returns `None` for its field, which gives consumers the choice to proceed with partial data or reject it. The alternative — fail-fast — would make the entire LIL fragile to transient failures in any single subsystem, which is unacceptable for a canonical profile that feeds the dashboard, tutor, and Telegram. Partial degradation makes the system robust at the cost of slightly more complex null-checking in consumers.
